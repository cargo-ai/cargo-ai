# Cargo AI 0.5.0 — Application Interface Milestone

Status: published on crates.io. [Product Qualification](https://github.com/cargo-ai/cargo-ai/actions/runs/39857311262) and [Registry Installation](https://github.com/cargo-ai/cargo-ai/actions/runs/39875868900) passed for `e8616a2a22f17631467573b7fcca97c5de67d02e` on Linux, macOS and Windows. Required OpenAI/Anthropic and supplemental Gemini/xAI/Jev checks passed. Mistral was rate-limited and its live availability remains unverified.

Cargo AI 0.5.0 brings its existing agent and package runtime to application callers through explicit machine contracts, portable actions and native AI roles. It is a larger product milestone under the [pre-1.0 versioning policy](../VERSIONING.md), while retaining supported human CLI usage and existing command-specific JSON interfaces.

## Integrate without parsing terminal output

Applications can discover the installed binary's capabilities and request typed JSON responses or the supported NDJSON runtime stream:

```sh
cargo ai capabilities --output-format json
cargo ai profile list --output-format json --output-schema-version 1
cargo ai run agent.json --output-format ndjson --max-runtime-in-sec 60
```

The [machine interface](../docs/machine-interface.md) defines response identities, errors, completion, cancellation and uncertain effects. A progress event or accepted operation is not a successful terminal result. Commands and revisions must be advertised by the selected binary; older CLI releases do not gain these contracts automatically. Existing flags such as `run --json` keep their original meanings.

## Declare portable actions and explicit result access

Packages and projects can expose named actions, bounded business inputs and optional presentation resources. A host discovers the catalog, validates inputs and supplies explicit execution policy and consent. Pages do not supply executable or shell commands. Clients retain responsibility for presentation, supervision and recovery; these contracts do not complete any particular host integration.

Selected tool results provide typed business data. Explicit private-content opt-in and separate host-held grants govern result content and bounded artifact reads. Resource discovery, validation, hashes and capability declarations do not authorize execution or grant filesystem access. See [portable client actions](../docs/client-actions.md) and [typed payloads](../docs/machine-payloads.md).

## Choose models and native role settings explicitly

Connection-aware model discovery and thinking controls expose supported selections without treating a model listing as proof of inference access. Account-backed OpenAI discovery uses an existing eligible Codex session; discovery does not start login or refresh credentials. Provider and credential-store limits remain documented in [model providers](../docs/providers/README.md).

Native roles give packages portable AI call declarations while hosts retain private profile/model choices and consent. Per-generation requests use editable role defaults and exact authorized overrides, resolved independently for each call. Capability evidence is informational; credential verification, scoped policy, revocation and adapter support still govern execution. No automatic model substitution, universal provider support or OS sandbox is implied.

## Compatibility and upgrade

- Supported human commands, legacy JSON interfaces and existing definitions retain their contracts. New machine and native modes are explicit opt-ins. The milestone number does not require rewriting every 0.4.x project.
- Discover supported versions before using them. Action catalogs 2 and 3 and requests 2, 3 and 4 have distinct semantics. Current per-generation choices use request 4/resolution 2/runtime 8/native selection policy 2; fixed request 3 remains supported separately. Interim catalog/request 1 is unavailable. These action protocols were introduced after the published 0.4.5 baseline.
- Installing a new CLI does not rebuild existing generated agents, tool bridges or installed package binaries. Rebuild to gain required runtime capabilities or resolve exact-provenance `out_of_sync` status. Re-resolve native requests when their runtime/source identity changes.
- Use `cargo ai guidance status` and explicitly choose `cargo ai guidance update` to receive current authoring guidance while preserving user-owned instructions. Hosts must implement the advertised bridge and consent contract; unsupported hosts must not guess a shell fallback.
- Existing usage tracking, backup consent and [0.4.5 compatibility limits](0.4.5.md#compatibility-and-upgrade) remain applicable. This release does not expand backup consent or automatically migrate historical data.

Install with `cargo install cargo-ai`. Fresh registry installation on Linux, macOS and Windows verified version 0.5.0, the exact published source and archive, direct/Cargo dispatch and a local action. These results do not establish host adoption or universal provider/media support.
