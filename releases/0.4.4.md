# cargo-ai 0.4.4

This release adds speech generation, recording transcription, expanded image providers and offline requirements inspection. Provider-specific limits and unverified routes are described below. See [release status](../docs/testing-and-release-qualification.md#release-status) for publication and verification evidence.

## Create speech and transcribe recordings

The `generate_audio` run step speaks supplied text into one local `.wav` or `.mp3` file. It needs a provider-specific voice and a compatible API-key profile selected for the invocation or step. OpenAI, Mistral and xAI adapters accept WAV or MP3 output; Gemini accepts WAV. Mistral needs an existing saved voice ID accessible to the account. Cargo AI does not create or clone voices. Returned audio is capped at 20 MiB and checked before it replaces an existing file. Mistral speech output has not been verified with a live voice.

The `transcribe_audio` run step reads one local WAV or MP3 file up to 10 MiB and captures a nonempty transcript for later steps in the same action. Its native routes support OpenAI API-key, Gemini, Mistral and xAI profiles. A parent can pass the capture to a following text child agent. An action-only parent can transcribe and forward the text without first running parent inference; a normal parent's initial inference happens before its actions. The selected Mistral transcription route has bounded live proof; provider access and model compatibility still depend on the selected account.

Speech and transcription are unavailable through OpenAI account transport, Anthropic, Ollama and TypeSafe. They do not add microphone capture, playback, streaming or generic model-facing audio input. See [actions and child agents](../docs/actions-and-child-agents.md#resolve-profiles-models-and-paths) and the [provider comparison](../docs/providers/README.md#choose-a-provider).

## Generate images through more providers

The existing `generate_image` step also has native Gemini, Mistral and xAI adapters. Gemini and xAI write JPEG (`.jpg` or `.jpeg`), while Mistral writes PNG without reference images. Gemini accepts up to four PNG/JPEG references; xAI accepts up to five. New adapter references are capped at 10 MiB each and 20 MiB total, and returned images at 20 MiB. Gemini output must be a real JPEG; Cargo AI rejects another returned format instead of relabeling it. Mistral's image tool may create a provider-hosted file before Cargo AI saves the local result. Mistral image generation remains unverified live.

OpenAI API-key/account image paths and Ollama's experimental PNG output without references retain their existing behavior. A provider profile must have access to a compatible image model; Cargo AI does not switch models or discard unsupported references. See [image actions](../docs/actions-and-child-agents.md#resolve-profiles-models-and-paths) and the [provider comparison](../docs/providers/README.md#choose-a-provider).

## Inspect declarations before execution

Use `cargo ai requirements --config FILE` to inspect one local agent definition, or `cargo ai requirements --build-profile NAME` to inspect the definitions explicitly selected by `[build.NAME]` in the current project. Local `cargo ai packages inspect ALIAS` shows the same declaration report when the installed package contains readable selected definitions. These operations report model-facing input/output needs, direct media steps and separate tools, assets and child references without running agents, tools, model requests or package builds.

Dynamic values, conditional steps and child agents that were not explicitly selected remain unresolved. The summary combines selected agents' requirements; it does not certify any model, account or whole package as compatible. See [packages](../docs/packages.md) and the [installed guidance workflow](../templates/guidance/package-workflow.md).

## Compatibility and upgrade

This is an additive release on the 0.4.x line. Existing supported definitions, CLI usage and OpenAI/Ollama image paths remain supported. Install or upgrade normally with `cargo install cargo-ai`, then check `cargo ai version`. Existing generated agents do not update automatically; re-hatch them when exact provenance reports `out_of_sync` or to use the new actions. Check `cargo ai guidance status` before explicitly running `cargo ai guidance update`; preserve modified guidance and user instructions.

The 0.4.3 local usage-history behavior continues: automatic local metadata collection can be disabled with `cargo ai usage settings --tracking off`. Account backup remains off by default and requires explicit enablement. See [0.4.3 notes](./0.4.3.md) for collection, consent and retention details, and [versioning](../VERSIONING.md) for the compatibility policy.
