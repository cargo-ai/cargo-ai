# cargo-ai 0.2.0

## What's New

- Establish a public pre-`1.0.0` versioning policy that treats Cargo AI as a product and CLI contract rather than a Rust library API.
- Add typed `runtime_vars` so invocation-scoped values can drive supported action logic and run-step behavior.
- Extend `generate_image` so it can work with Ollama's experimental OpenAI-compatible image-generation path, including mixed-provider flows where the parent stays on OpenAI and the image step switches to an Ollama profile.
- Add explicit parallel top-level action execution while keeping each individual action's `run` steps sequential.
- Improve parent/child workflow ergonomics with named reusable inputs, child runtime-var forwarding, and validator alignment for the additive contract.
- Continue polishing key Cargo AI CLI surfaces so the release is easier to understand and operate.

## Why This Is 0.2.0

This release meaningfully expands the user-facing Cargo AI contract compared with `0.1.0`, so it is larger than a patch-level `0.1.1` release. It still stops short of a `1.0.0` stability promise.

See [VERSIONING.md](../VERSIONING.md) for the public versioning policy.

## Upgrade

```bash
cargo install cargo-ai --locked
```

To check whether a newer crates.io version is available:

```bash
cargo ai version --check
```
