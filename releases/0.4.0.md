# cargo-ai 0.4.0

## Compatibility and migration

This release starts the `0.4.x` compatibility line. Review existing definitions and scripts before upgrading from `0.3.x`.

- Agent definitions require `agent_definition_schema_version`; the old top-level `version` key is rejected. Preserve the existing schema revision when renaming that key. Adopting the current strict revision, `2026-09-09.r1`, also requires reviewing the complete definition against the [definition contract](../docs/agent-definitions.md). Changing the header alone does not migrate a definition.
- Package, shared-agent and mail operations use the top-level `cargo ai packages`, `cargo ai agents` and `cargo ai mail` commands. The former account-heavy command paths are removed; `cargo ai account` manages the account lifecycle. Update scripts using the [package](../docs/packages.md) and [account/sharing](../docs/accounts-and-sharing.md) guides and installed command help.
- Run or hatch account-hosted definitions with top-level `cargo ai run` / `cargo ai hatch` and `--from-account` or `--owner-handle`; these execution commands do not move under `agents`.
- Generated agents embed exact Cargo AI provenance. Re-hatch agents that report `out_of_sync` after reviewing their definitions. Existing installed packages and tools are not silently rebuilt during a CLI upgrade.
- Final hatched agents, build outputs and source-backed installed tools compile with Cargo's release profile. Default project build output is now `target/cargo-ai/build/<profile>/<target>/release/`; update scripts that expect the former output location. Hatch `--check` continues to validate without exporting a binary.
- Sampling temperature is opt-in. Unset temperature sends no override; an explicit value still must be supported by the selected provider and model. Existing explicit profile values remain explicit.
- Noninteractive `cargo ai account register` requires `--yes` to acknowledge that registration may reactivate an account and cancel a pending deletion request. Review that effect before updating automation.

## Local ownership and packages

- Install source packages under local aliases, inspect their contents, and manage supported version transitions while preserving separate mutable package data.
- Declare project-owned runtime data independently of distributable source. Packaging excludes runtime data, credentials and mutable author-machine state.
- Inspect hosted source/version identity, package contents, digest, declared permissions and provenance before acquiring a specific immutable version. New subprocess permission requests require explicit acceptance; source-tool compilation is not an operating-system sandbox.
- Pull shared packages back into editable project-shaped source and rebuild supported tools locally. Hosted sharing remains optional for local execution.
- Install version-matched authoring guidance while preserving user-owned instructions and files. The Animal Patrol source example demonstrates a structured image finding and a project-owned CSV tool.

## Providers and accounts

- Add first-class Anthropic, Gemini, xAI and Mistral adapters alongside OpenAI and Ollama. Provider/model capabilities remain explicit; unsupported image, file or sampling behavior fails with guidance.
- Add account deactivation and deletion-request commands with explicit confirmation. Hosting credentials and runtime-provider credentials remain separate.

## Security and installation

- Remove credential-bearing custom URL details from provider diagnostics and runtime status output.
- Bound decompressed hosted archive input before tar extension metadata is parsed, retaining entry/path limits and transactional installation behavior.
- Make `cargo install cargo-ai` the normal installation and upgrade command. Release checks retain locked dependency verification and also exercise freshly resolved packaged-source installations on the supported native CI platforms.
- Keep `--locked` available for [dependency reproduction](../docs/install/cargo.md#optional-dependency-reproduction). Dependency resolution can change after publication; release-time results do not guarantee every future dependency combination.

## Upgrade

```bash
cargo install cargo-ai
cargo ai version
```

Use the current stable Rust toolchain and review the migration notes above. The rolling, unsigned Windows preview remains separate from official versioned releases. See [Versioning](../VERSIONING.md) and [Installation](../docs/install/README.md).
