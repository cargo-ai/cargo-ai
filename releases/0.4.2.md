# cargo-ai 0.4.2

## TypeSafe Jev support

- Connect to hosted Jev inference through a normal API-key profile with `--server typesafe`. Cargo AI remains a local Rust client; selected text is sent to TypeSafe. No companion runtime or local model weights are required.
- Use described string enums for **Choice** and explicit bounded numeric rubrics for **Score**, including both in one definition. Text and client-fetched URL text work through interpreted execution and hatched native executables. Validated labels and scores feed the existing actions and tools.
- Check declared compatibility before compilation with `cargo ai hatch triage --config ./triage.json --check --profile jev`. The selected profile is a check target, not a profile embedded into the generated executable. Runtime checks the actual inputs and effective provider.
- Author rubric scores with definition revision `2026-09-19.r1`. Ordered rubric levels map Jev's native score linearly to the authored inclusive numeric range, preserving fractions. Other compatible providers receive the rubric and range as instructions.

Jev supports a defined subset: flat described enum choices and explicit rubric scores. Image/file inputs, free-form or nested outputs, integers, booleans and numbers without rubrics are unsupported. Leave temperature and max-output-tokens unset. Unsupported combinations fail explicitly; no automatic conversion, fallback or inference retry is added. Static checks do not certify credentials, token fit, live model availability or answer quality.

See [TypeSafe setup and limits](../docs/providers/typesafe.md) and the [Choice/Score example](../templates/guidance/examples/jev-choice-score.json).

## Explicit profile selection

`cargo ai run --profile NAME` now fails if the named profile cannot be resolved, including when no profile configuration exists. It no longer silently selects the default profile or continues with manually supplied connection settings. Repair the named profile, or omit `--profile` when intentionally supplying the connection manually. Default selection when no profile is explicitly requested retains its existing behavior.

## Compatibility and upgrade

This is an additive release on the 0.4.x compatibility line. Existing strict and legacy definition contracts remain supported; ordinary scaffolds retain `2026-09-09.r1`. The new rubric revision supports local and hatched execution; hosted account storage of that revision is deferred. No Cargo AI account is required for local Jev execution, but TypeSafe API access is required.

Install or upgrade normally:

```bash
cargo install cargo-ai
cargo ai version
```

For an exact 0.4.2 installation, use `cargo install cargo-ai --version 0.4.2`. Existing hatched agents may report `out_of_sync` after an upgrade because provenance checks are exact; re-hatch to use the updated runtime and new rubric definitions. See [versioning](../VERSIONING.md) and [installation](../docs/install/README.md).
