# cargo-ai 0.4.3

## Automatic local usage history

Starting with 0.4.3, Cargo AI runs and newly hatched agents collect local usage metadata by default. History is stored under the selected Cargo AI Home at `usage/usage.sqlite3` and persists until you explicitly delete it. No Cargo AI account or background service is required.

To stop new automatic collection while keeping existing history:

```bash
cargo ai usage settings --tracking off
```

Use `CARGO_AI_USAGE_TRACKING=off` to disable collection for a process and its children. Explicit `--usage-log` and `CARGO_AI_USAGE_LOG` NDJSON exports remain independent of automatic collection.

Query recorded runs and usage through the versioned JSON interface:

```bash
cargo ai usage settings --json
cargo ai usage runs --json
cargo ai usage summary --json
cargo ai usage summary --json --provider typesafe
```

History includes run, agent, tool and provider-request facts, available token counters, requested and returned model identifiers, timings and bounded outcomes. Missing counters remain unknown; Cargo AI does not estimate monetary costs or actual charges. Local history excludes prompts, model output, tool payloads, credentials and raw provider errors. Capture covers requests observable to Cargo AI, not a provider's internal work.

SQLite is embedded in the CLI and generated binaries, so it needs no separately installed database engine. Source builds require the supported Rust and C toolchains. Keep the live database on a local filesystem, outside network shares and cloud-synchronized folders. Automatic collection failures do not change the agent's result, but an unwritable home or terminated process can lose unwritten facts; history is not a guarantee of complete capture.

See [Cargo AI Home](../docs/cargo-ai-home.md#usage-history) and the [usage contract](../templates/guidance/usage-ledger.md#automatic-history-and-cli-json) for filtering, pagination, export, deletion and coverage details.

## Optional account backup and restore

Cloud backup is **off by default**. Signing in does not enable it. Explicit enablement selects future records; including older history requires a separate preview and confirmation. Collection, upload, local deletion and cloud deletion have separate controls.

```bash
cargo ai usage backup status --json
cargo ai usage backup enable --json
```

The first command reads local state. Enabling backup uses the signed-in account. Enabled runtimes make bounded upload attempts when a root run completes; offline failures retain account-bound queues. Account changes do not redirect an old queue. Disabling upload preserves local history and queued selections; requests already transmitted may finish.

Backup sends a restricted metadata projection, excluding local paths and user-authored labels as well as prompts, responses, tool payloads and credentials. Restore preserves original event identities to avoid double-counting, retains existing local labels and excludes restored records from automatic re-upload. Restored labels can be opaque IDs. Cloud deletion leaves local history intact and revokes the old upload generation so stale queues cannot repopulate it.

See [backup and restore](../docs/usage-backup.md) for consent-bound previews, explicit sync, restore pagination, deletion and failure behavior. Backup does not continuously merge device histories or copy the live SQLite database. Cloud availability does not determine agent success.

## Compatibility and upgrade

This release preserves the supported 0.4.x definition and CLI contracts. Default-on local metadata collection is the main change to existing run behavior; use the opt-out above if you do not want it. Existing generated binaries retain their original behavior. Rebuild or re-hatch them to use automatic history and optional backup; exact provenance checks may report `out_of_sync` after a CLI upgrade.

Install or upgrade normally:

```bash
cargo install cargo-ai
cargo ai version
```

Verified on 2026-09-22: 0.4.3 is available from crates.io; [release evidence](../docs/testing-and-release-qualification.md#release-status) records the exact source, native installation checks and provider limitations. Existing project guidance updates through the supported explicit `cargo ai guidance update` operation; inspect `cargo ai guidance status` first and preserve modified guidance and user instructions.
